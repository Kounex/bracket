# Configuration

## Backend

Copy `ci.env` to `prod.env` and fill in the values:

- `PG_DSN`: The URL of the PostgreSQL database
- `JWT_SECRET`: Create a random secret using `openssl rand -hex 32`
- `CORS_ORIGINS` and `CORS_ORIGIN_REGEX`: Specify allowed frontend domain names for CORS (see the
  [FastAPI docs](https://fastapi.tiangolo.com/tutorial/cors/))
- `ADMIN_EMAIL` and `ADMIN_PASSWORD`: The credentials of the admin user, which is created when
  initializing the database
- `SENTRY_DSN`: The [Sentry](https://sentry.io) DSN  for monitoring and error tracking
- `BASE_URL`: The base url of the API used for SSO
- `ALLOW_USER_REGISTRATION`: Can be used to disallow user registration in the web app, currently
  used for production while bracket is still in beta
- `ALLOW_INSECURE_HTTP_SSO`: Should not be used in production. Allows use of INSECURE requests for
  SSO auth.
- `AUTO_RUN_MIGRATIONS`: Whether to run (alembic) migrations automatically on startup or not.
  Migrations can be applied manually using `uv run alembic upgrade head`.
- `SERVE_FRONTEND`: Lets the FastAPI backend serve the frontend's static files itself. Only used
  by the self-built combined image (root `Dockerfile`); the published split images don't use it.
- `API_PREFIX`: Set to `/api` in Docker deployments. This makes all the backend requests go to
  `localhost:8400/api/ping` instead of `localhost:8400/ping`, and lets the frontend's Caddy proxy
  (or any reverse proxy) forward API requests by path prefix. The frontend's `API_BASE_URL` must
  contain this prefix as well.

### Backend: Example configuration file

This is an example of how the config file should look like:

```bash
PG_DSN='postgresql://bracket_ci:bracket_ci@localhost:5532/bracket_ci'
JWT_SECRET='60eed5c5dc7a919b8595a23d6c42ddd8274e4feea651dc028d9bee495bbb9acd'
CORS_ORIGINS='https://bracket.mydomain.com'
CORS_ORIGIN_REGEX='https://.*\.vercel\.app'
ADMIN_EMAIL='admin@example.com'
ADMIN_PASSWORD='some unused password'
SENTRY_DSN='my sentry dsn'
ALLOW_USER_REGISTRATION=false
ALLOW_INSECURE_HTTP_SSO=false
CAPTCHA_SECRET='xxx'
AUTO_RUN_MIGRATIONS=true
API_PREFIX=/api
```

## Frontend

In Docker deployments, the frontend is configured at **container start** via environment variables
(the entrypoint writes them to `config.js`, which takes precedence over any build-time values):

- `API_BASE_URL`: The base URL of the backend API to which the frontend sends requests.
  Use the relative `/api` together with the Caddy proxy setup (see the
  [Docker deployment docs](../deployment/docker.mdx)), or an absolute URL like
  `https://api.bracket.com/api`.

The following `VITE_*` variables are **build-time** only (local development or self-built images);
they have no effect on the published Docker images:

- `VITE_API_BASE_URL`: Build-time fallback for `API_BASE_URL`.
- `VITE_HCAPTCHA_SITE_KEY`: The HCaptcha key used for captcha challenges when creating new
  accounts. You get the secret when you create a new site in HCaptcha. The published images are
  built without a captcha key.
- `VITE_ANALYTICS_DATA_DOMAIN`: The `data-domain` attribute passed to the script for Plausible
  analytics
- `VITE_ANALYTICS_DATA_WEBSITE_ID`: The `data-website-id` attribute passed to the script for Umami
  analytics
- `VITE_ANALYTICS_SCRIPT_SRC`: The URL to the script for analytics purposes.

### Frontend: Example configuration file

For local development, you can store the build-time config in `.env.local` (as described in the
[Vite docs][vite-config-url]).

This is an example of how the config file should look like:

```shell
VITE_HCAPTCHA_SITE_KEY='10000000-ffff-ffff-ffff-000000000001'
VITE_API_BASE_URL='https://api.bracket.com'
VITE_ANALYTICS_SCRIPT_SRC='https://analytics.bracket.com/script.js'
VITE_ANALYTICS_DATA_DOMAIN='bracket.com'
VITE_ANALYTICS_DATA_WEBSITE_ID='bracket.com'
```

[vite-config-url]: https://vite.dev/guide/env-and-mode
